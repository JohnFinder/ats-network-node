# ATS operator services

The operator services index confirmed V2 contract events, serve a signed publication catalog, and can run independent observer and settlement processes. The package requires Node.js 24 and pins ethers 6.15.0. Give the service identity, observer wallet, and settlement wallet separate keys. Providers and publishers must use different wallets from observers. Settlement depends on a trusted threshold committee and the retrieval evidence it collects.

## Configuration

| Setting | Value |
| --- | --- |
| `SERVICE_RPC_URL` | Explicit chain RPC URL. Use HTTPS outside development. |
| `SERVICE_CHAIN_ID` | Expected chain ID. |
| `SERVICE_DEPLOYMENT_MANIFEST` | Read-only path to the JSON manifest generated by [the V2 deploy script](../contracts/scripts/deploy-v2.mjs). |
| `SERVICE_PUBLIC_URL` | HTTPS origin of this service. |
| `SERVICE_APPROVED_NODES` | JSON array of `{url,providerID}` pairs. Provider IDs are SHA-256 fingerprints of raw Ed25519 public keys. |
| `SERVICE_APPROVED_INDEXERS` | JSON array of `{url,serviceID}` pairs for trusted indexers. |
| `SERVICE_DATA_DIR` | Writable persistent storage. Defaults to `./data`. The container runs as UID 1000. |
| `SERVICE_SIGNING_KEY_FILE` | Optional DER PKCS#8 Ed25519 private key file. By default the service creates a mode-0600 identity in its data volume. |
| `SERVICE_CONFIRMATIONS` | 12 blocks by default. |
| `SERVICE_POLL_MS` | 5000 milliseconds by default. |
| `SERVICE_MAX_AUDIT_BYTES` | 1 GiB by default. Full-file audits stream the object. |
| `SERVICE_CATALOG_CHECK_SECONDS` | 3600 seconds by default. Catalog checks expire when sources disappear. |

With [the services Compose file](../compose.services.yaml), set `SERVICE_MANIFEST_FILE` to the absolute host path of the reviewed manifest. Compose mounts it read-only and sets the container manifest path.

The manifest supplies ABIs and runtime code commitments. The service takes the RPC endpoint from its own configuration and refuses to start if the RPC chain, deployed code, or saved database deployment differs from the configured deployment.

The indexer fetches from pinned origins and rejects redirects. It checks confirmed metadata hashes and the publisher's original signed upload request from the pinned node. A successful retrieval with a matching full SHA-256 is required before a publication can enter the catalog. Metadata requires a confirmed publication. Catalog entries identify the source of their rankings. Node download counts describe activity at the nodes that collected them.

For deployments with content moderation, the catalog also requires an approved signed origin descriptor and approved status at the pinned source. Metadata replication checks approval when serving the metadata. See the [operator moderation workflow](../docs/OPERATIONS.md#content-moderation).

### Data and recovery

The SQLite WAL database holds canonical block hashes and events, metadata, dual-signature binding proofs, wallet intents, lease nonces, schedules, and audit evidence. On restart the service resumes from its cursor and checks canonical block hashes. Use encrypted, consistent snapshots that include the WAL. Restore against the explicitly configured RPC so the index can revalidate the chain.

To replay from the deployment block, stop the running instance and run `node src/main.mjs --rebuild` from `services/`. Give each process its own writable database. For a disposable development network, `SERVICE_ALLOW_HTTP=true` permits HTTP origins such as Compose service names, and `SERVICE_CONFIRMATIONS=0` removes confirmation delay. Keep the development RPC private and leave the Docker socket outside the service container.

## Observers and settlement

Mount the observer key at `SERVICE_OBSERVER_KEY_FILE=/run/secrets/observer_key`. The optional coordinator key uses `SERVICE_SETTLEMENT_KEY_FILE=/run/secrets/settlement_key`. Raw key environment variables require explicit development mode. Each observer needs a separate data volume and a funded EVM account authorized by the market committee. An unauthorized observer refuses startup. An account with zero gas pauses financial actions. Rotate or revoke committee members through contract administration.

For each prepaid period the observer schedules three jittered retrieval challenges by default. Set `SERVICE_AUDIT_SAMPLES` up to 20 and `SERVICE_OBSERVER_WORK` to control the audit operations per tick (default two). The observer checks the provider's signature, confirmed dual binding and full object bytes. A missed window counts as a failure. Observers can agree on a report when their period, policy and success count match. Individual signed observations are available separately. Keep the committee independent of the providers. A colluding committee can agree on false observations, and a retrieval result cannot establish that several independent replicas exist.

The permissionless coordinator calls `settlePeriod` once the threshold is met, the review delay has elapsed, and the committee generation and round still match without an open challenge. Status can show `retry_pending`, unauthorized or `insufficient_gas`. Retry frequency follows the poll interval. Resolve disputes through the administrator's external wallet. On shutdown, the service drains work for up to 15 seconds and reconciles outstanding transactions with durable chain state when it restarts.

## API reference

| Endpoint | Behavior |
| --- | --- |
| `GET /v2/network` | Deployment commitments, pinned nodes, and health for indexing, observation, and settlement. |
| `GET /v2/catalog?q=&cursor=&limit=` | Signed and paginated chain-confirmed catalog, newest first, with block and source provenance. |
| `GET /v2/metadata/:sha256` | Signed exact metadata bytes for pinned indexers. |
| `GET /v2/identity/:fingerprint`, `GET /v2/account/:fingerprint` | Confirmed identity and local dual proof, publications, orders and settlements. `edProofVerified=true` requires a verified Ed25519 proof. |
| `GET /v2/orders/:numericId/lease` | Signed node retention receipt for a confirmed prepaid active order with a dual-verified provider binding. It carries a fresh timestamp, durable monotonic nonce, cached receipt UUID for retries and EVM order ID encoded as bytes32. Trust the service Ed25519 fingerprint as a settlement issuer on the node. Check later with the issuer for revocation or early termination. |
| `GET /v2/observations?orderID=` | Bounded signed audit records for the requested order. |

The API bounds payload size, cursors, open intents, concurrency, origins and request rate. Operators configure RPCs, source origins, keys, ABIs, and transaction destinations.

## External wallet workflow

1. Request the current nonce with `GET /v2/binding-nonce?wallet=0x…`. Send `{walletAddress,publicKey,nonce,expiresAt,chainId,registry,statement,signature}` to `POST /v2/binding-intents` with a base64 Ed25519 signature over the exact [binding statement](../contracts/README.md#identity-and-external-wallets), without a trailing newline.
2. Open `GET /wallet?intent=<uuid>` on the service. The page uses a CSP and an EIP-1193 wallet. The chain and account must match the intent. The user reviews the typed message and pays for the transaction from the external wallet.
3. Use `GET /v2/binding-intents/:id` and `POST /v2/binding-intents/:id/complete` for the binding and publication intents. Completion checks the wallet signature and confirmed contract state.

Browser intent URLs expire after ten minutes. The signed binding has its own lifetime, 90 days by default in the ATS client and operator CLI, up to 366 days. Revoke or renew it through an explicit wallet transaction.

For publication, open `GET /wallet/publish?node=<approvedOrigin>&resource=<uuid>` or send `{nodeURL,resourceID}` to `POST /v2/publication-intents`. The service verifies the source and binding before building the plan. The wallet path assigns 100% of the royalty split to the publisher and commits the reviewed public metadata in the signature. Use the contract directly for other splits. Publication does not request a token transfer approval.

### Wallet management

Open `GET /wallet/manage` for bond, exact token approval, storage quote and order, royalty, task, retained milestone, refund, and reward actions. The review shows the token's reported decimals, chain, destination, method and arguments, with expandable calldata. Import signed quotes and reward vouchers as bounded JSON. Each operation needs a separate wallet confirmation. Editing an input invalidates its prior preview. The service restricts destinations and ABIs and defaults to exact approvals.

## Local verification

Use a disposable chain 1337, a deployed V2 manifest and a running service. Run these commands from `services/`:

```sh
SERVICE_VERIFY_URL=http://127.0.0.1:8790 npm run verify
SERVICE_VERIFY_PRIVATE_KEY_FILE=/run/secrets/dev_verify_key npm run verify -- --binding
SERVICE_DEPLOYMENT_MANIFEST=/contracts/artifacts/deployment.v2.1337.json npm run verify -- --reorg
```

The binding exercise spends gas from the supplied development signer. The reorg exercise snapshots and rewinds the test chain. Use separate observer secrets and volumes for a multi-observer exercise, and advance the clock through each scheduled retrieval window to exercise actual observations. Reserve this CLI for disposable environments.

### V2 local Docker record — 2026-10-16

The [Docker verifier](../scripts/verify-services-docker.sh) passed on a freshly compiled chain 1337 deployment using a synthetic public archive, valueless test tokens, two observer identities and volumes, and a separate coordinator. All containers ran on one physical host. The run exercised provider and publisher dual proofs, canonical upload metadata, catalog full-file checks, node lease acceptance and idempotent retry, retrieval windows, threshold voting, challenge blocking, renewed review after resolution, full payout, missed-window refund, signed observations, restart, reorganization and index rebuild.

The recorded review moved identity lookup to canonical events, prioritized verified dual proofs, required the exact lease provider, and cached idempotent receipts with monotonic renewal. It also invalidated derived evidence on reorg or rebuild, checked canonical orders and committee generations before voting, and reused publication intents before downloading archives. This record covers local functional verification. Independent operation and security review are separate deployment requirements.
